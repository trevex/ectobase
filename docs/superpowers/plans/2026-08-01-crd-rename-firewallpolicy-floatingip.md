# CRD Rename: FirewallPolicy + FloatingIP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename two CRD kinds to end name collisions and improve clarity: `NetworkPolicy` → `FirewallPolicy` (collides with core `networking.k8s.io` NetworkPolicy — the confirmed source of the vpc-peering ambiguous-delete bug) and `VirtualIP` → `FloatingIP` (semantic). Add shortNames `fwpol` / `fip`.

**Architecture:** Pure control-plane/API rename. Types live in `api/v1alpha1`; CRD manifests + deepcopy are regenerated by `make generate` (controller-gen + `hack/sync-chart-crds.sh`, which fully rebuilds `deploy/charts/ectobase/crd-bases`). The only real Go consumer of these kinds is `netplane/controllers/compilednic.go` (compiles FirewallPolicy → `CompiledNIC.firewall`). `VirtualIP`/`FloatingIP` is a schema-only type with NO controller/agent/datapath wiring. The `flowplane-*` datapath consumes `CompiledFwRule`, never the CRD — so ZERO verifier/datapath code changes. Group/version stay `net.ectobase.dev/v1alpha1`; alpha + dev-only fabric → no conversion webhook, no back-compat alias (delete old CRD, apply new).

**Tech Stack:** Go (controller-runtime, kubebuilder markers, controller-gen 0.20.1), Kustomize, Helm, bash scenarios, containerlab/kind fabric. `make generate` requires the nix devShell (controller-gen on PATH — confirmed).
